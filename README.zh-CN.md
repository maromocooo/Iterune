# Attune

**从实际结果出发，持续改进编码智能体的行为。**

Attune 是一款本地优先的 macOS 应用，用于回顾 Skill 的执行结果，并改进背后的指令。查看 Prompt、Output 和 Feedback，从不理想的结果中形成改进提案，审阅差异，再保存为新版本。只有你明确选择 Publish 时，改动才会写回原始 Skill 文件。

目前，Attune 专注于 Claude Code、Codex 和 Gemini CLI 的 **Skill**。它可以独立使用：浏览、本地编辑和版本管理不需要 API key，也不依赖其他项目。AI 功能是可选的。

## 为什么选择 Attune

我们经常在任务开始前修改智能体指令，却很少把实际结果与下一次修改联系起来。Attune 将结果回顾和指令改进放进同一个流程：

```text
Prompt → 智能体输出 → 审阅与反馈 → 改进 Skill → 保存版本 → 再次尝试
```

Skill 目录只是起点。更重要的是根据实际结果决定改什么、审阅改动，并保留可以恢复的版本。你仍需在平时使用的智能体环境中重新执行任务；Attune 不会自动重跑任务，也不会自动判断改动是否提高了质量。

## 当前功能

- **回顾执行结果：**导入受支持的本地历史，或手动记录已有结果；查看 Prompt、Output、模型、评分、反馈及产物引用。
- **提出有针对性的改进：**输入整体修改要求，或选中 `SKILL.md` 中的文字添加评论，再生成 AI 提案；也支持直接编辑和离线本地模板。
- **审阅后再保存：**查看原文的 diff。AI 修改必须能唯一、明确地匹配原文；重叠或无效的 patch 会被拒绝。改进草稿可以保存并继续编辑。
- **管理与恢复版本：**在应用库中保存版本，将旧版本恢复为新的修订，不删除中间的历史。
- **区分参考结果与编辑基准：**分别显示参考 run 的关联版本和固定的编辑基准版本。旧 run 或版本未知的 run 也能作为改进参考。
- **按需 Publish：**应用库的修改与原始文件分开管理，写回前执行源文件保护、外部变更检查和备份。
- **用熟悉的语言阅读：**应用界面支持英语、日语、简体中文和繁体中文。可选的 `SKILL.md` AI 翻译仅用于阅读，不会改写原文或保存为翻译后的 Skill 版本。

历史记录会说明版本关联的依据：

| 关联方式 | 含义 |
| --- | --- |
| 内容匹配 | 完整读取的文本与已保存版本逐字节一致。同一内容可能属于多个修订；Attune 会保留候选，而不是任意选定一个。 |
| 手动关联 | 用户选择了版本，并非在执行时观测到的版本。 |
| 版本未知 | 读取不完整、格式不受支持、证据冲突，或没有匹配的保存版本；手动记录时也可以不指定版本。 |
| 旧数据关联，未经验证 | 保留已有的旧关联，但不声称它符合当前验证规则。 |

读取记录或文本匹配**不能证明**智能体调用了 Skill、遵循了指令，或在执行时使用了某个特定修订。重复导入会按历史合并规则保留已有的版本关联及用户评分、反馈。

## 使用流程

1. 让 Attune 发现本地 Skill，添加项目文件夹，或先体验有明确标识的演示库。
2. 导入受支持的本地历史，或通过 **Add run** 手动记录已有结果。
3. 阅读 Prompt 和 Output，添加评分或反馈。
4. 打开 **Improve Skill**，或选中 Skill 文本添加评论。分别确认参考 run 和编辑基准版本。
5. 选择服务提供方和模型，生成提案，或在本地编辑。将 run 的 Prompt、Output 和 Feedback 发送给 AI 的选项**默认关闭**。
6. 审阅 diff，保存为应用库中的新版本。如果编辑基准发生变化，需要先处理冲突，不会悄悄改为针对另一个版本保存。
7. 对于允许写回的源文件，在需要时打开 **Publish to source…**，确认目标路径、固定版本和源文件差异后再提交。
8. 在平时使用的环境中重新运行编码智能体，查看新的结果，继续改进。

## 支持的智能体

| 智能体 | Skill 发现 | 本地历史导入 |
| --- | --- | --- |
| Claude Code | 用户和项目 Skill、同步 Skill、plugin cache | 受支持的成功 `Read` 结果及已完成轮次；不包含 sidechain 记录。 |
| Codex | 用户、项目、共享位置，以及本地/内置区域、plugin cache 和管理员目录 | 受支持的 `item_completed` JSONL 中的 Skill 读取记录与已完成轮次。 |
| Gemini CLI | 用户、项目、共享 Skill 和扩展目录 | 受支持的会话 JSON/JSONL 中的 `read_file`，或能识别源路径的 `activate_skill` 结果，以及已完成回答。 |

这些 adapter 只覆盖特定路径和日志格式，并不支持各智能体的全部功能或所有版本。导入针对当前选中的本地 Skill，不是完整的调用遥测。设置中可以控制是否导入、时间范围和排除文件夹。缺少证据或格式不受支持时，版本可能未知；仍可手动记录结果。发现 Skill 不代表有权覆盖其源文件。

AI 改进和翻译目前支持 **Codex CLI、Claude CLI、OpenAI API 和 Anthropic API**。可以使用已登录的 CLI，或配置 API key 和模型。Gemini 的目录与历史支持不包含 Gemini AI 服务连接。改进和翻译可以分别设置模型。

## 源文件保护与 Publish

**在应用库中保存或恢复版本，不会修改原始 `SKILL.md`。** 写回源文件是单独的明确操作。

- 已验证的用户、项目和共享本地来源，通过当前文件状态及所有权检查后，才允许 Publish。
- plugin cache、同步、托管、内置和扩展来源的源文件保持只读；其历史、改进提案和应用库版本管理仍可使用。
- 来源未知时需要重新检查；无法分类的源文件仍受保护。演示 Skill 或缺失的源文件不能 Publish。符号链接、硬链接等不安全目标也会被拒绝。

确认时会固定待写入版本、目标路径及用于比较的源内容。Attune 按字节检查外部变更，替换前创建私有备份；如果确认后状态发生变化，会要求重新审阅。这些保护由核心写入逻辑执行，不仅仅依赖界面上的禁用按钮。

应用库中的编辑版本与**最近一次观测到的源文件内容**分别显示。最近一次观测不保证磁盘内容仍然相同，也不代表智能体当前使用的版本。重新扫描发现外部修改时，会保留尚未 Publish 的应用库编辑，供你比较差异。

Publish 不是跨外部编辑器和应用库数据库的完整事务，仍存在短暂的外部编辑竞争窗口。如果源文件已写入但数据库保存失败，Attune 会说明部分成功、保留备份，并要求重新扫描后再重试，不会无条件回滚源文件。

## 安装与构建

**目前尚无正式签名并公证的 Attune 发行版。** 请在 **macOS 14 或更新版本**上，使用 **Xcode 15 或更新版本及 Swift 5.9 或更新版本**从源码构建。应用使用 SwiftUI 和系统 SQLite，不依赖外部 Swift package。

```sh
git clone https://github.com/maromocooo/Attune.git
cd Attune
swift build
swift test
bash scripts/build-app.sh
open "dist/Attune.app"
```

开发时可以运行 `swift run Attune`，或在 Xcode 中打开 `Package.swift`，选择 **Attune / My Mac**。本地应用构建默认采用 ad-hoc 签名，没有 Developer ID 签名或公证。请在计划试用的 Mac 上构建；这不是下载正式签名应用的流程。

可通过 `STUDIO_UNIVERSAL=1 bash scripts/build-app.sh` 构建 Universal 版本。详见[构建与发行流程](RELEASING.md)和[验证范围及已知限制](VERIFICATION.md)。为 Intel 交叉编译不能替代 Intel Mac 实机测试。

启动时，Attune 会扫描受支持的 Skill 位置；未发现 Skill 时打开演示库。可以在 **Local skills / Demo library** 之间切换。演示模式仍会执行 Skill 发现，不是隔离的测试环境。

## 隐私

- **本地优先：**应用库、run 历史、版本和草稿存储在本地 SQLite 中。扫描和历史导入不会将这些记录发送给 AI，也不会执行日志中的命令。
- **AI 请求可选：**生成 AI 改进提案时，会向配置的服务提供方发送 Skill 原文、修改要求及选中的引文和上下文。参考 run 的 Prompt、Output 和 Feedback 仅在明确选择后才会附加，该选项默认关闭。提交文本本身包含的信息仍会被发送。
- **翻译仅供阅读：**请求 AI 翻译会将当前显示的 Skill 文本发送给所选服务，改变的是视图，而不是源文件。包括 CLI 连接在内，AI 改进和翻译都可能受服务条款、网络要求及使用费用影响。
- **凭据：**API key 保存在 macOS Keychain 中，不写入应用库或备份。CLI 认证由 CLI 自己管理。离线使用应用库无需 API key。
- **明确写回：**扫描和保存应用库版本不会触发 Publish，也不会悄悄覆盖受保护的外部管理源文件。

设置中提供应用库导出和恢复。备份包含 Skill 文本及会话数据，请作为私有数据保管；Attune 不会对其加密。备份不包含 API key、CLI 凭据或产物的实际文件。产物记录只是引用和元数据，不是历史文件内容的快照。

## 当前限制

- 仅支持 macOS；当前编辑和版本管理的单位是 `SKILL.md` 正文，不会将相关 scripts、references 和 assets 作为完整包进行版本管理。
- 历史导入尽力而为。host 格式可能变化，无法保证捕捉每次调用、每个结果或确定其关联版本。
- AI 改进需要配置服务并审阅提案，不保证输出质量一定提高。
- 尚无智能体自动重跑、自动质量评估或产物 Before/After 对比。
- 在启动、重新扫描和项目变更时发现源文件，没有持续文件监控。
- 正式发行以及更广泛的环境与无障碍验证尚未完成，详见[验证记录](VERIFICATION.md)。

## 未来方向

Attune 目前专注于 Skill。我们希望探索将**使用 → 回顾结果 → 提供反馈 → 持续调优**的流程，扩展到更广泛的编码智能体指令与配置，例如 `CLAUDE.md`、`AGENTS.md`、rules、plugins 及其他智能体配置。

这些文件与 plugin 的管理功能**目前尚未实现**。这代表探索方向，不承诺交付顺序或发布时间。即使范围逐步扩展，Attune 也应始终能够独立使用。
