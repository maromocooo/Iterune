# Iterune

**結果を見ながら、エージェントを調律する。**

Iteruneは *iterate*（反復）と *tune*（調律）を合わせた名前です。使って、結果を見て、指示を改善し、また試す。その繰り返しで望む振る舞いへ近づけていきます。

Iteruneは、Skillを使った結果を振り返り、その指示を改善するためのローカルファーストなmacOSアプリです。Prompt・Output・Feedbackを確認し、期待に届かなかった結果から改善案を作り、差分をレビューして版として保存します。元のSkillへ反映するのは、必要なときに明示的にPublishした場合だけです。

現在の対象は、Claude Code・Codex・Gemini CLIの**Skill**です。Iteruneは単体で利用でき、閲覧・ローカル編集・版管理にAPIキーや別プロジェクトは必要ありません。AI機能は任意です。

## Why Iterune — 結果と改善をつなぐ

エージェントへの指示は実行前に編集しても、実際の結果を見た後の修正とは切り離されがちです。Iteruneは、結果の振り返りから次の指示の変更までを一つの流れにします。

```text
Prompt → エージェントの出力 → レビュー・Feedback → Skillの改善 → 版として保存 → 再び試す
```

Skillの一覧はその出発点です。実際の結果から修正箇所を考え、変更を確認し、戻せる版を残すことを目指します。再実行は普段使っているエージェント側で行います。Iteruneがタスクを自動で再実行したり、品質の改善を判定したりする機能はありません。

## 現在できること

- **実行結果を振り返る:** 対応するローカル履歴の取込、または手動登録で、Prompt・Output・モデル・評価・Feedback・成果物の参照を確認できます。
- **改善点を指示する:** Skill全体への指示や`SKILL.md`の選択箇所へのコメントからAI改善案を作るほか、直接編集にも対応。オフラインのローカルテンプレートも使えます。
- **差分を確認して保存する:** 原文の差分をレビューします。AIの変更は原文の一箇所に曖昧さなく一致する必要があり、重複・不正なpatchは拒否します。改善下書きの保存・再開にも対応しています。
- **版を残し、戻す:** ライブラリに新版を保存し、過去版を新しいrevisionとして復元します。途中の履歴は消しません。
- **参考にした結果と編集対象を区別する:** runの関連版と、固定された編集基準版を別表示します。古いrunや版不明のrunも改善の参考にできます。
- **必要なときだけPublishする:** ライブラリの変更と元ファイルを分離し、sourceの保護・外部変更チェック・backupを経て反映します。
- **読みやすい言語で確認する:** アプリは英語・日本語・简体中文・繁體中文に対応。任意の`SKILL.md` AI翻訳は閲覧専用で、元ファイルの書換えや翻訳版の保存は行いません。

履歴には、版の関連付けの根拠を表示します。

| 関連付け | 意味 |
| --- | --- |
| 保存本文と一致 | 完全に読み取れた本文が保存版とbyte単位で一致。同じ本文の版が複数あれば、一つに決めず候補を保持します。 |
| ユーザーによる関連付け | ユーザーが版を選択したもの。実行時に観測した版ではありません。 |
| 版は不明 | 部分読取・未対応形式・矛盾した読取・一致する保存版なし等。手動登録でも版を不明のまま残せます。 |
| 旧データの関連付け・未検証 | 以前の関連付けを保持しますが、現在の検証基準を満たすとは扱いません。 |

読取記録や本文一致だけでは、Skillの呼出し・指示への遵守・実行時に使用した特定revisionの**証明にはなりません**。再取込では履歴のmerge規則に従い、既存の関連付けとユーザーの評価・Feedbackを保持します。

## 使い方

1. ローカルSkillを自動検出するか、プロジェクトフォルダを追加します。明示的に区別されたデモライブラリから試すこともできます。
2. 対応するローカル履歴を取り込むか、**実行を追加**から既存の結果を登録します。
3. PromptとOutputを読み、評価やFeedbackを残します。
4. **Skillを改善**を開くか、本文の選択箇所にコメントします。参考runと編集基準版をそれぞれ確認します。
5. 接続先・モデルを選んで改善案を生成するか、ローカルで編集します。runのPrompt・Output・FeedbackをAIへ送る設定は、**初期状態ではOFF**です。
6. 差分を確認し、ライブラリに新版を保存します。途中で編集基準版が変わった場合は、黙って別版へ保存せず競合の解消を求めます。
7. 必要があり、書込みを許可されたsourceなら、**元ファイルへ反映…**で対象の版・保存先・差分を確認してPublishします。
8. 普段の環境でエージェントをもう一度実行し、次の結果から改善を続けます。

## 対応エージェント

| エージェント | Skillの検出 | ローカル履歴の取込 |
| --- | --- | --- |
| Claude Code | user/project Skill、synced Skill、plugin cache | 対応形式の成功した`Read`結果と完了ターン。sidechainは対象外です。 |
| Codex | user/project/shared、local/bundled領域、plugin cache、管理者root | 対応する`item_completed` JSONLのSkill読取と完了ターン。 |
| Gemini CLI | user/project/shared Skill、extension領域 | 対応する会話JSON/JSONLの`read_file`、または元パスが特定できる`activate_skill`結果と完了回答。 |

adapterは特定のパス・ログ形式に対応しており、各エージェントの全機能・全versionを網羅するものではありません。取込は選択中のローカルSkillを対象とし、すべての呼出しを捕捉する仕組みではありません。設定で取込の有効化・対象期間・除外フォルダを調整できます。根拠の不足や未対応形式で版が不明になる場合も、手動登録を利用できます。検出できることと、元ファイルへ書き込めることは別です。

AI改善・翻訳の接続先は現在、**Codex CLI・Claude CLI・OpenAI API・Anthropic API**です。ログイン済みCLIを使うか、APIキーとモデルを設定します。GeminiのSkill・履歴対応に、GeminiのAI接続は含まれません。改善用と翻訳用のモデル設定は分けられます。

## 元ファイルの保護とPublish

**ライブラリで版を保存・復元しても、元の`SKILL.md`は変わりません。** 元ファイルへのPublishは別の明示操作です。

- 確認済みのuser/project/sharedローカルsourceは、現在のファイル・所有権のチェックを通った場合に反映できます。
- plugin cache・synced・managed・bundled・extensionの元sourceには直接反映しません。履歴の閲覧、改善案の作成、ライブラリ内の版管理は利用できます。
- 由来が不明なsourceは再確認が必要で、分類できないものは保護を続けます。デモ・元ファイルなしのSkillはPublishできません。symlink・hardlinkなど安全を確認できない対象も拒否します。

確認画面を開いた時点の版・保存先・比較元の内容を固定します。外部変更はbyte単位で確認し、置換前にprivate backupを作成します。確認後に状態が変われば、再確認を求めます。これらの保護は、ボタンの無効化だけでなくcoreの書込み処理でも行います。

ライブラリの編集版と、**元ファイルで最後に確認した内容**は別表示です。最終確認は、現在のdisk内容やエージェントが使っている版の保証ではありません。再scanで外部変更が見つかっても、未反映のライブラリ編集は保持し、差分を確認できます。

Publishは、外部エディタとライブラリDBをまたぐ完全なtransactionではなく、小さな競合の余地が残ります。source反映後にDB保存が失敗した場合は、部分成功を表示してbackupを保持し、再試行前に再scanを求めます。元ファイルを無条件に巻き戻すことはしません。

## インストール・ビルド

**正式に署名・公証したIteruneのReleaseはまだありません。** **macOS 14以降**、**Xcode 15以降・Swift 5.9以降**でソースからビルドしてください。SwiftUIとシステムのSQLiteを使い、外部Swiftパッケージへの依存はありません。

```sh
git clone https://github.com/maromocooo/Iterune.git
cd Iterune
swift build
swift test
bash scripts/build-app.sh
open "dist/Iterune.app"
```

開発・SwiftUI Previewでは、**隔離したデータディレクトリの明示指定が必須**です。Debug buildが通常ライブラリへfallbackすることはありません。専用launcherは毎回新しい開発用アプリをbuildし、合成Skill・履歴だけを使います。外部サービスとsource Publishは無効で、通常DB・WAL・SHMのファイルfingerprintが変わらないことも確認します。

```sh
bash scripts/run-gui-smoke.sh
# または、新しい空のprivateディレクトリを指定してDebug版を起動:
SKILL_STUDIO_DATA_DIR="$(mktemp -d /private/tmp/iterune-dev.XXXXXX)" swift run Iterune
```

Xcodeでは、実行・Previewの環境変数`SKILL_STUDIO_DATA_DIR`に空のprivateディレクトリを指定してください。未指定・相対path・通常領域・fixtureのmarkerがない既存データは拒否します。開発設定はメモリ内に保持し、API/CLI経由のAI・Keychain・実履歴・source Publishは利用しません。開発アプリを終了するとsmoke検証が完了し、privateな検証記録は既定で残ります。`--headless`はウィンドウを開かずfixture storeを確認します。

通常のReleaseアプリは、既存ライブラリの保存先と設定を引き続き使います。ローカルbuildはad-hoc署名で、Developer ID署名・公証は行いません。署名済みアプリのダウンロード手順ではありません。

Universal版は`STUDIO_UNIVERSAL=1 bash scripts/build-app.sh`で作成できます。詳しくは[ビルド・配布手順](RELEASING.md)と[検証範囲・既知の制約](VERIFICATION.md)を参照してください。Intel向けのcross-compileは、Intel実機での検証とは別です。

通常のproduction起動時に対応するSkillの保存場所をscanし、見つからなければデモライブラリを開きます。**ローカルSkill / デモライブラリ**は切替可能です。デモモードでも実Skillの検出は動くため、隔離されたテスト環境ではありません。

## Privacy

- **ローカルファースト:** ライブラリ・run履歴・版・下書きはローカルのSQLiteへ保存します。scanや履歴取込では、その記録をAIへ送信せず、ログ中のcommandも実行しません。
- **AI送信は任意:** AI改善案の生成時には、原文Skill・修正指示・選択した引用と文脈を設定済みproviderへ送ります。参考runのPrompt・Output・Feedbackは明示的に選んだ場合だけ追加し、初期状態ではOFFです。送る本文に含まれている情報は、そのまま送信対象になります。
- **翻訳は閲覧専用:** AI翻訳を依頼すると、表示中のSkill本文を選んだproviderへ送信します。変わるのは表示で、元ファイルではありません。AI改善・翻訳にはCLI接続を含め、providerの利用条件・ネットワーク接続・利用料金が適用される場合があります。
- **認証情報:** APIキーはmacOS Keychainへ保存し、ライブラリやbackupには含めません。CLIの認証はCLI側で管理します。オフラインのライブラリ利用にAPIキーは不要です。
- **明示的なsource書込み:** scanやライブラリ保存だけではPublishしません。保護された外部管理sourceを勝手に上書きしません。

設定からライブラリをexport／restoreできます。backupにはSkill本文・会話データが含まれるためprivateに扱ってください。Iteruneによる暗号化は行いません。APIキー・CLI認証・成果物の実ファイルは含まれません。成果物の記録は参照・metadataであり、過去時点のファイル内容のsnapshotではありません。

## 現在の制約

- macOS専用です。編集・版管理の単位は`SKILL.md`本文で、関連するscripts・references・assetsをまとめて版管理する機能はありません。
- 履歴取込はbest effortです。hostの形式変更や根拠不足により、すべての呼出し・結果の捕捉や版の特定はできません。
- AI改善には接続設定と提案のレビューが必要で、出力品質の向上を保証するものではありません。
- agentの自動再実行、自動品質評価、成果物のBefore/After比較は未実装です。
- sourceの検出は起動時・再scan・プロジェクト変更時に行います。常時ファイル監視はありません。
- 正式配布や、より広い環境・アクセシビリティの検証は未完了です。[検証記録](VERIFICATION.md)も参照してください。

## 今後の方向性

現在のIteruneはSkillが中心です。将来的には、**使う → 結果を見る → フィードバックする → 調律する**という流れを、`CLAUDE.md`、`AGENTS.md`、rules、pluginsなど、Coding Agentの振る舞いに影響する指示・設定へ広げていきたいと考えています。

これらのファイルやpluginの管理は、**現在は未実装**です。提供順序や時期を約束するロードマップではなく、今後探っていく方向性です。対象が広がっても、Iterune単体で使えることを大切にします。
